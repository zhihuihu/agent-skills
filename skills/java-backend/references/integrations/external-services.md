# 外部服务集成

通过清晰的端口表示外部能力，适配器负责 HTTP 客户端、认证、协议 DTO 与本地业务概念之间的转换。沿用项目已有客户端和配置方式。

用例需要第三方能力时，可在所属业务范围的 `application.port` 定义只使用本地类型的接口，例如 `ShippingRateGateway`；实现放在 `infrastructure.client.shipping`，第三方请求、响应 DTO 及认证、超时配置也留在该适配器附近。直接调用第三方 SDK 的封装同样属于 `infrastructure.client`。复杂项目将这些包放在对应限界上下文内；确实由多个上下文共享的接入能力应提供明确的共享接口，避免各上下文依赖另一个上下文的客户端内部类。若只是简单调用且项目已有清晰做法，不必机械地新增一层端口。

- 识别调用方需要的结果、超时上限和失败处理；不要把第三方响应结构直接传播到领域层。
- 重试前确认请求是否幂等，设置次数与退避策略，并考虑上游已发生副作用的情况。
- 区分调用失败、第三方拒绝和本地业务拒绝，提供可诊断但不泄露密钥的日志。
- 契约变化时检查兼容性；对关键调用使用项目现有的桩服务或契约测试方式。
- 凭据和地址从配置读取，不写入源码或示例真实值。
