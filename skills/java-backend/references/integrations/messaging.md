# 消息集成

区分进程内领域事件与跨进程集成消息。发送给其他系统的消息需要稳定契约、版本策略和明确的数据所有者。沿用项目已使用的 Kafka、RabbitMQ 或其他消息系统。

- 说明消息何时产生、事务提交与发布之间如何协调；需要更强可靠性时评估现有 outbox 等机制。
- 消费端按实际投递语义处理重复消息；为副作用定义幂等条件。
- 确认顺序要求、分区或路由键、失败重试及死信处理。无限重试和多层重试会放大故障。
- 载荷只携带消费者需要的稳定信息，避免直接序列化聚合或 JPA 实体。
- 测试生产和消费两端的关键契约，以及重复、失败等会影响业务结果的情况。

具体配置按项目版本查阅 [Spring Boot 消息文档](https://docs.spring.io/spring-boot/reference/messaging/index.html) 和所选消息组件文档。
