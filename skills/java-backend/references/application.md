# 应用层

一个用例应清楚表达输入、业务结果和失败条件。用例服务负责加载聚合、调用领域行为、协调仓储与外部端口，并返回用例结果；业务不变量由领域对象维护。简单项目将用例服务放在 `shop.application`，复杂项目放在对应上下文的 `application` 包。

- 将需要原子完成的修改放在合适的事务边界内。新用例通常以 `application` 层的用例方法或应用服务为事务边界；已有项目先核对并遵循现有边界，避免让 Controller 或领域实体承担事务编排。使用 `@Transactional` 时确认调用经过 Spring 代理；同类内部调用及新线程中的操作不能仅凭外层注解假定处于同一事务。先识别数据库事务能覆盖的资源，再决定跨系统一致性策略。
- 对重复请求、并发修改和重试有要求时，明确幂等键、版本检查或唯一约束等机制。不要只靠接口名称暗示幂等。
- 查询不触及聚合不变量时，可以使用专门的读取模型；无需为此引入完整 CQRS 基础设施。
- 通过端口表达外部能力，让用例不依赖 HTTP 客户端、消息客户端或缓存库的具体类型。现有项目采用其他清晰做法时保持一致。
- 明确区分业务失败与技术失败，交给入口层映射为相应协议响应。

应用层的事务、异步执行和事件发布方式应与项目版本及现有实现一致。涉及 Spring 事务语义时参阅项目对应版本的 [Spring 事务文档](https://docs.spring.io/spring-framework/reference/data-access/transaction.html)。
